fix(web): 门牌墙按设计原则重做（色块面积 + 竖向门牌），并修正 Taro 的 px 换算

## 真机验证暴露的问题

首次在浏览器里跑起来后发现：设计计划里写的"**状态用色块面积表达**，远处一眼
可辨"根本没落实——实际是 3px 底边 + 文字着色，等于细线；而且 7 个门牌挤成
一排小方块，不是设计的竖向矩形。

## 根因：Taro 的 pxtransform

`designWidth: 750` 会把**所有小写 px** 当作"750 宽设计稿"的尺寸换算。
我写的 `minmax(96px, 1fr)` 实际渲染约 50px，所以一屏挤下 6~7 列。
Taro 的官方约定是**大写 PX 表示不换算**。

修正：需要真实屏幕像素的地方用 `PX`（门牌高度、网格最小列宽）；
随屏幕缩放的间距与字号保持小写 `px`。

## 视觉重做

- **整块着色**：底色 + 文字色同时承载状态，`$state-surface` 与 `$state-ink`
  两组 map 一一对应。新增状态若漏登记，Sass 编译期即报错
- **门牌竖向**：固定高度 116PX，一屏 3 列放下全部 7 个
- 底边压深一档（`rgb(0 0 0 / 8%)`）给方形一个落地感，仍然不用阴影
- 文案 "7 个位" → "7 个喷头"

## 其他修正

- **dev proxy 前缀太宽**：`'/api'` 把源码路径（`src/api/client.ts` 在模块图里
  暴露为 `/api/client.ts`）也代理到服务端，返回 404 导致白屏。改为 `'^/api/v1'`
- **`map-get` → `map.get`**：全局函数已弃用，Dart Sass 3.0 将移除
- `index.html` 的 `<title>` 仍是模板的 "we"；`apple-mobile-web-app-capable`
  改为新标准 `mobile-web-app-capable`（消除浏览器弃用告警）
- `config/dev.ts` 的 proxen target 支持 `TARO_APP_API_TARGET` 覆写，
  便于对着生产数据做本地视觉验证
