feat(web): 门牌墙页面 + 设计 token + API 层，前端质量门全绿

## 门牌墙

用户最常用的入口：站在浴室门口看一眼判断有无空位，因此页面上不放任何
需要先阅读才懂的东西——标题一行，其余全是门牌。

- `DoorPlate`：竖向矩形（真实浴室隔间是竖的，不是正方形也不是卡片）。
  门号是主角（最大字号 + 最重字重 + 收紧字距），状态文字是说明
- `DoorWall`：窄缝网格（`$space-sm`，像瓷砖缝），用 auto-fill 而非固定列数——
  设备门数不同，固定列数会在门数变化时留空位
- 空态给说明而非空白

## 设计 token：颜色只有一处定义

`styles/_tokens.scss` 按浴室真实材质取色（瓷砖、水、不锈钢），刻意避开常见
生成式设计套路（暖米色底 + 陶土色、近黑底 + 酸绿、发丝线报纸版式、统一圆角
卡片套件）。

**7 个状态收敛为 4 个色组**：只有 `free` 用强色（用户找的就是它），
waiting/bathing/paused 同为"有人"，repair/disabled 同为"坏了"，
selected 为过渡态。

关键约束：**颜色只存在于 SCSS**。状态映射到 `door--<state>` 类名，
由 `app.scss` 的 `@each` 从 token map 生成——TS 侧只给类名，不碰颜色，
因此不存在"JS 一套色、CSS 一套色"的漂移。新增状态若忘记登记 token，
Sass 编译期即报错。

## API 层：类型从契约生成，不手写

- `server/scripts/export_openapi.py`：导出 OpenAPI 到 `web/openapi.json`，
  并抽查 `DoorState` 枚举是否在列（缺失即失败，早于前端拿到残缺类型）
- `pnpm gen:types`：用 openapi-typescript 生成 `src/api/schema.d.ts`（71 KB）
- 生成的 `DoorState: "free" | "waiting" | ...` 联合类型正是此前把服务端
  `DoorView.state` 从裸 str 改成枚举的目的——前端因此有编译期检查

`ApiError` 解析服务端统一的 RFC 9457 问题体；错误体不是 problem+json 时
退回状态码而不吞掉失败。

## 质量门

前端不能是唯一没有门禁的部分（服务端 96%、设备端 98%）。四个脚本全部接入，
当前全绿：typecheck（严格模式）、lint、stylelint、coverage。

## 过程中修掉的坑（每处都有具体原因）

- 官方模板 `tsconfig` 是 `noImplicitAny: false`，三端里最松 → 改 `strict: true`
  + `noUncheckedIndexedAccess` + `noImplicitOverride` + `noFallthroughCasesInSwitch`；
  `baseUrl` 已弃用（TS 7.0 移除）故不加，`paths` 相对 tsconfig 解析
- `stylelint-config-standard` 不认 SCSS 语法（`//` 注释报 CssSyntaxError）
  → 改用 `stylelint-config-standard-scss`，并登记小程序内置标签 `page`
- testing-library 需要 vitest `globals: true` 才会自动 cleanup，否则同一文件
  多次 render 会累积 DOM 并报 getMultipleElementsFoundError
- `@vitejs/plugin-react` 的类型基于 rollup 4，与项目 Vite 4 的 rollup 3 无法
  赋值 → vitest 配置不引入该插件，JSX 交给内置 esbuild
- hook 测试缺 `act` 包裹会产生 React 警告；mock 未在 beforeEach 重置会让
  调用次数断言累积
- `app.scss` 的 `@use` 与状态类改完后，`index.tsx` 引用的 `index.scss` 被我
  误删（删前未查引用）→ 补回并写入页面布局
