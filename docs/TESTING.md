# 测试策略

本文件记录本项目的测试策略、层级、环境、数据、覆盖率政策与证据。测试规则的所有者是 [`STANDARDS.md`](../STANDARDS.md) 第 10 章；本文件记录本项目的实例。测试命令在 [`CONTRIBUTING.md`](../CONTRIBUTING.md) 的「质量门」小节；本文不复制命令。

## 原则

- 测试强度与变更级别成正比：R0 做文档检查，R1 做单元与集成，R2 加契约与端到端，R3 加安全、恢复与现场验证。
- 测试必须确定：时间、随机数、网络、文件系统与设备状态通过参数或接口注入。
- 测试必须隔离：每个用例自建数据并清理，不依赖其他用例的残留状态。
- 测试数据必须合成或脱敏；不得使用真实学号、口令、令牌与个人信息。
- 测试不得访问生产环境、生产数据库或真实外部服务；需要真实设备时在受控环境执行并记录。
- 每个缺陷修复先有能复现缺陷的测试，再修代码。
- 不得用重试、增加等待或放宽断言掩盖不稳定测试。

## 层级

| 层级 | 目标 | 范围 | 运行时机 |
|---|---|---|---|
| 单元 | 验证纯逻辑与边界 | 单个模块，无外部 IO | 每次提交 |
| 集成 | 验证模块与真实依赖协作 | 数据库、路由、协议编解码 | 每次提交 |
| 契约 | 验证三端与 Schema 一致 | 协议、OpenAPI、生成物 | 每次提交 |
| 端到端 | 验证关键用户路径 | 服务端、网页端、模拟设备 | 合并前 |
| 现场 | 验证真实设备行为 | 设备、网络、外部系统 | R3 与发布前 |
| 回归 | 防止已修复缺陷重现 | 缺陷相关路径 | 每次修复 |
| 非功能 | 验证性能、安全、可访问性与恢复 | 关键接口与界面 | 发布前 |

## 测试设计

- 验收条件逐条对应测试；无法自动化的必须有现场验证记录。
- 边界与状态机使用等价类、边界值、判定表与状态迁移覆盖。
- 时间、时长与时钟相关逻辑使用注入时钟与固定样本。
- 重复投递、乱序、超时、断线、重启与部分失败必须有测试。
- 测试名称说明行为与条件；失败消息包含期望值、实际值与输入。
- 测试不得使用 `sleep` 等待；异步等待使用事件、条件或受控时钟。
- 单条测试有 5 秒超时；超时表示用例在等待一个不会到达的事件。

## 数据与环境

| 环境 | 用途 | 数据 | 访问 |
|---|---|---|---|
| 本地 | 开发与调试 | 合成数据或脱敏副本 | 开发者 |
| 持续集成 | 自动检查 | 合成数据 | 自动任务 |
| 生产 | 真实服务 | 真实数据 | 只读；不得运行测试 |

- 本地数据库可以删除重建；生产数据库不得删除重建。
- 生产数据进入本地前必须脱敏。
- 真实设备测试记录设备型号、系统版本、网络条件与执行时间。
- 测试日志与报告由持续集成保存，不入库。

## 覆盖率

- 覆盖率门槛在持续集成配置中定义，只升不降。
- 覆盖率是下限，不是目标；关键分支必须有显式测试。
- 排除项逐条说明原因；不得用全局排除掩盖未测试代码。
- 新增关键逻辑不得降低覆盖率；覆盖率下降的变更不得合并。
- 覆盖率与测试数量由持续集成输出；文档不写死。

## 当前自动化范围

| 范围 | 框架与入口 | 说明 |
|---|---|---|
| 服务端 | pytest；`server/tests/` | 单元、集成、契约、接口与真实数据回放 |
| 设备端 | JUnit；`android/app/src/test/` | 纯逻辑、协议、时钟、队列、语音与设备状态机 |
| 协议契约 | pytest 与 Kotlin 测试；`server/tests/test_contract_sync.py`、`android/app/src/test/.../GeneratedContractTest.kt` | 生成物逐字节一致与三端动作集合对账 |
| 时间轴模型 | `tools/timeline_model/` 与 `server/tests/test_derivation_edges.py` | 参考模型与边界用例 |
| 网页端 | 浏览器手工验证 | 零构建静态页面；关键路径按可访问性与交互检查 |
| 现场 | 真机与生产只读观测 | 设备行为、网络、OTA 与外部系统 |

当前自动化范围只描述入口，不写测试数量与覆盖率数值；数值由持续集成输出。

## 安全测试

- R3 变更执行威胁模型复核与针对性安全测试。
- Web 端按 OWASP ASVS 5.0.0 选取适用条目；设备端按 OWASP MASVS 2.1.0 选取适用条目。
- 覆盖身份与授权、输入校验、输出编码、SQL 注入、命令注入、路径穿越、文件上传、敏感数据暴露、错误处理与依赖漏洞。
- 依赖漏洞扫描按 [`SECURITY.md`](SECURITY.md) 的发布检查执行。
- 安全测试证据写入发布记录。

## 可访问性测试

- 网页端满足 WCAG 2.2 AA。
- 自动检查覆盖结构、标签、对比度与目标尺寸；人工检查覆盖键盘、焦点、缩放与屏幕阅读器。
- 颜色不得作为唯一信息载体；错误必须同时有文字说明。
- 阻塞关键任务的可访问性问题按 S2 处理；严重级别定义见 `STANDARDS.md` §16.7。

## 性能与恢复测试

- 关键接口定义时延目标与测量方法；变更影响性能时复测。
- 设备命令验证超时、重试、重复回执与断线恢复。
- 数据库验证备份、还原与完整性检查。
- 队列与连接验证上限、背压与恢复。
- 性能与恢复测试结果写入发布记录。

## 不稳定测试

- 不稳定测试是缺陷，不是环境噪声。
- 定位不确定性来源：时间、并发、网络、顺序、共享状态或随机数。
- 修复方式是消除不确定性；不得用增加等待、自动重试或放宽断言掩盖。
- 无法立即修复时隔离并记录责任人、原因与恢复日期；隔离不是删除。

## 证据

- 测试报告、覆盖率、现场记录、部署后验证与监控数据由发布记录引用。
- 验收条件未满足时必须列为未完成项，不得用“后续改进”代替验收。
- 缺陷记录包含环境、版本、复现步骤、期望结果、实际结果、影响面、证据、严重级别与责任人。
- 缺陷与审阅发现的严重级别统一按 `STANDARDS.md` §16.7；缺陷处置按 §10.6。
