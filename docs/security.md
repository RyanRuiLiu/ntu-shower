# 安全与隐私

本文件记录本项目的资产、数据分级、信任边界、威胁模型、控制选择与事件响应。本文件记录本项目的安全规则、实例与证据。系统结构见 [`architecture.md`](architecture.md)，运维步骤见 [`runbook.md`](runbook.md)。

## 资产与数据分级

| 资产 | 分级 | 存放位置 | 处理要求 |
|---|---|---|---|
| 公开状态、学号（等同姓名，业主裁定 2026-11-14）、公开文档 | 公开 | 仓库、公开接口 | 可公开；保证完整性 |
| 架构、运行手册、非敏感配置 | 内部 | 仓库、服务器配置 | 仅协作者可读 |
| 使用记录、设备标识、审计记录 | 机密 | 生产数据库、审计表 | 最小权限；传输与存储加密；不写入文档与测试 |
| 学生浴室口令、账号口令、凭据令牌 | 受限 | 生产数据库（只存哈希）、签发时一次性下发 | 专用保管；访问审计；不写入日志与文档 |
| APK 签名密钥与私钥 | 受限 | `android/ntu-shower.keystore`（gitignore）+ 异地备份 | 加密存储；访问审计；备份与轮换 |
| 数据库、发布物、备份 | 机密 | 服务器数据目录与备份目录 | 最小权限（备份目录 700）；恢复演练；备份加密暂不执行——例外见 `docs/adr/` ADR-0018 |
| 源代码、测试、协议 Schema | 内部 | 仓库 | 按仓库权限管理；不包含真实个人信息 |

数据分级方案由本文「资产与数据分级」规定；本表只记录本项目的资产实例。

## 信任边界

| 边界 | 一侧 | 另一侧 | 控制 |
|---|---|---|---|
| 设备边界 | Android 中控设备 | 校园网络 | 设备身份、TLS、服务端信任名单、命令审计 |
| 网络边界 | 校园网络与公网 | 服务端 | nginx 443 入口、TLS、防火墙、速率限制 |
| 管理边界 | 浏览器 | 服务端 | 签名会话 Cookie（操作者全权）、口令 Argon2id、审计 |
| 消费边界 | `status-panel` 与其他消费方 | 服务端 | 公开接口与 scope 接口分离；`ntushower_` 密钥；契约变更通知 |
| 设备调试边界 | 运维者 | 设备 root shell 与 ADB | 按需开启、一次性 nonce、仅回环、空闲回收、审计 |

设备物理接触假设：设备位于浴室现场，攻击者取得物理接触后可读取设备存储、操作 root shell 或替换 APK。依赖物理安全的控制必须写明这个前提；远程控制不能假设设备端绝对可信。

## 威胁模型

威胁分类使用 STRIDE：身份伪造、数据篡改、否认、信息泄露、拒绝服务、权限提升。每个改动安全控制、数据删除、设备控制或 OTA 的变更必须更新本节并记录剩余风险。

| 威胁 | 场景 | 控制 | 剩余风险 |
|---|---|---|---|
| 身份伪造 | 未授权设备连接网关；调用方伪造身份 | 设备身份与信任名单；Bearer/会话；scope 守卫与作用域；TLS | 设备标识不是第二凭据；物理接触设备后可冒用 |
| 数据篡改 | 修改审计、会话或配置 | 数据库约束；审计只追加；配置登记表校验；备份校验 | 拥有数据库写权限的运维者可以改库；审计记录不是不可抵赖证据 |
| 否认 | 调用方否认执行过操作 | 审计记录包含身份、来源 IP、请求与结果；命令审计关联 `trace_id` | 单运维者环境缺少独立第三方见证 |
| 信息泄露 | 日志、错误、备份或前端泄露个人信息 | 日志脱敏；错误不返回内部细节；备份加密；访问最小权限 | 会话 Cookie 为 HttpOnly，脚本不可读；XSS 仍可能以会话身份发请求，依赖 XSS 防护与 SameSite |
| 拒绝服务 | 高频请求、超大上传、长连接占满 | nginx 速率限制；请求体上限；队列有界；连接数限制 | 单机部署；大规模流量仍可造成服务不可用 |
| 权限提升 | 普通身份调用管理面；设备端命令越权 | scope 守卫；URL 不表达权限；默认拒绝；命令白名单 | 密钥被窃取后拥有其 scope 集内全部能力 |

## 身份与授权

- 查看类接口公开；其余接口要求 Bearer 密钥或签名会话 Cookie。
- 权限与设备作用域都附在**密钥**上（GitHub fine-grained PAT 同型）：权限回答“能做什么”（RFC 6749 scope 语义，`resource:action` 命名），作用域回答“对哪些设备做”。
- 没有注册流程；用户与密钥由管理员签发、编辑与撤销。撤销立即生效（守卫每请求查库）。
- 密钥默认永不过期、多枚共存；轮换 = 发新枚 → 切换 → 吊销旧枚。凭据带 `ntushower_` 前缀。
- 管理台口令（Argon2id）只属于用户；会话通道视为操作者全权，权限只存密钥一处。
- 管理面与用户面使用同一套授权判断与审计；不存在绕过审计的特权通道。
- 会话生命周期：空闲超时 + 滑动续期 + 绝对超时，全部服务端强制（OWASP Session CS）。
- 凭据不可枚举；只通过 TLS 传输；不写入日志与文档。

授权实现入口：`server/app/auth/`。权限字典：`server/app/auth/permissions.py`（唯一出处）。

## 密钥与凭据

- APK 签名密钥位于 `android/ntu-shower.keystore`（gitignore），签名配置在 `android/keystore.properties`；备份与恢复步骤见 [`runbook.md`](runbook.md)。
- 生产配置由 Compose 的 `env_file` 注入；`.env` 不入库；仓库只保留 `.env.example` 的键名与占位符。
- 密钥必须有唯一保管人、异地备份、访问记录与轮换方案。轮换不得中断服务。
- 密钥、口令、令牌与签名材料不得写入代码、镜像、日志、文档、测试与提交信息。
- 签名密钥丢失会导致所有在网设备无法覆盖安装，必须物理接触重装。备份必须定期校验。

## 设备与远程操作

- 设备端只申请必要权限；无障碍服务、root shell 与开机自启都是受控能力。
- 远程调试通道按需开启、一次性 nonce、仅绑定回环地址、空闲回收并审计；不对公网开放任何端口。
- 设备端敏感数据保存在应用私有目录；共享存储不写入口令、令牌与完整学号。
- 设备日志不包含口令、令牌、完整学号与剪贴板内容。
- OTA 必须校验版本、校验和与签名；安装失败停止重试并留下记录。
- 设备控制命令必须有授权、超时、终态与审计；不得留下未定义的物理状态。
- 命令执行使用参数数组与固定路径；不得拼接未校验的输入。

## Web 与 API

- 全站使用 HTTPS；HTTP 自动跳转 HTTPS。
- nginx 配置 HSTS、`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、内容安全策略（CSP）与 API 速率限制。
- 身份标识只通过加密通道传输；不放在 URL 查询参数中。
- 跨源访问默认同源；需要跨源时使用允许列表，不使用通配符。
- 错误响应使用 RFC 9457 问题详情；不返回堆栈、SQL、内部路径与密钥。
- 关键接口有请求大小限制；资源耗尽返回明确错误。
- 前端不使用未转义的外部内容写入 `innerHTML`；所有输出按上下文编码。
- 网页端会话 Cookie 由浏览器自动携带，HttpOnly + SameSite=Lax；XSS 防护是会话不被滥用的前提。

## 供应链

- 运行依赖与开发依赖分开声明；生产版本锁定在 `requirements.txt`。
- 每次包含代码或依赖变更的发布生成依赖清单与软件物料清单（SBOM，SPDX 或 CycloneDX）。
- 依赖漏洞扫描进入发布检查；高危与严重漏洞修复前不得发布。
- 发布物有校验和；APK 使用正式签名；下载方必须校验。
- 构建环境与发布权限最小化；构建脚本变更按高风险变更审阅。

## 日志、审计与隐私

- 审计覆盖身份变更、权限变更、配置变更、发布、回滚、数据修正与设备控制命令。
- 审计记录只追加；访问最小权限；导出记录；保留期由配置项 `audit_retention_days` 定义（默认值见 `app/core/config.py`）。
- 设备端落盘文件全部有界，无需人工清理；数据库由 LiteStream sidecar 持续复制到
  `/var/backups/ntu-shower/litestream`（部署见 `docs/runbook.md`）。
- 日志是事件流；不包含口令、令牌、密钥与完整敏感请求体（学号按业主裁定为公开信息，可入日志）。
- 审计表是受限存储：请求体与命令参数保留原文，包括浴室口令；仅最小权限可读，导出留痕。stdout 日志不写这些字段。
- 只收集完成功能所需的最少个人数据；个人数据有明确用途、保留期与访问权限。
- 个人数据不写入文档、测试、日志与提交信息；必要展示必须脱敏。
- 数据导出与删除经过批准并记录；第三方共享说明目的、范围与保护措施。
- 新增个人数据字段或新增处理目的时执行隐私影响评估。

## 事件响应

- 安全事件按本文的「事件响应」处置；复盘按 `runbook.md` 的「复盘」执行。
- 处置顺序：保护人身与设备安全 → 阻止影响扩大 → 恢复服务 → 保留证据 → 根因分析。
- 保留证据：日志、审计、网络记录、文件校验和与时间线。
- 评估影响范围：数据、身份、设备、密钥与外部系统。
- 通知相关方；通知内容准确、可核对，不作推断。
- 恢复后轮换受影响密钥与身份，并验证无残留访问。
- 复盘针对系统与流程；改进项有责任人、期限与验证方式。
