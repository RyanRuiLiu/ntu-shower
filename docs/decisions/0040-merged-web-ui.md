# 0040. 网页端：合并旧系统的两个页面，零构建静态文件

* 状态：accepted
* 日期：2026-09-30

## 背景与问题

旧系统（ntu-remote-shower）有两个各自独立的网页端：

| 位置 | 端口 | 作用 |
|---|---|---|
| `shower-server/app/debug/index.html` | 5020 | 调试面板：KPI、门牌墙、分配/结算/拍照、事件日志 |
| `bridge-server/src/viewer.html` | 7003 | 画面查看器：实时画面、远程点击、无障碍节点树 |

两者用了**同一个视觉主题**（GitHub 暗色）却**各写一份 CSS 变量**，色值彼此不一致
（绿色一处 `#22c55e`、一处 `#3fb950`；变量名 `--bg-surface` 与 `--surface` 混用）。
维护两套样式意味着任何视觉调整都要改两处，而它们本就是一体的界面。

## 考虑过的选项

* **保持两个独立页面** —— 继续维护两套样式，色值分歧会持续扩大
* **合并为一个页面 + 视图切换**（采纳）
* 引入前端框架重做 —— 曾试过（Taro，见 ADR-0039），成本远超收益

## 决策结果

合并为 `server/web/` 下的**零构建静态文件**，由服务端本身托管在根路径：

```
server/web/
  index.html     单页：顶部导航切换两个视图
  app.css        设计令牌 + 共享元素（顶栏、按钮、表单）
  app.js         API 封装、WebSocket、视图切换、共享状态
  status.css/js  状态视图：KPI + 门牌墙 + 操作 + 日志
  control.css/js 遥控视图：实时画面
```

### 视觉：只统一色值，其余不变

用户明确要求"风格不变"。合并时以 **GitHub 官方色值**为准（主题本就是它），
变量名统一到 `--*`，布局、间距、圆角、动效全部照搬。

### 文案：改用术语表

配色与排版不变，但文案改用 `docs/CONTENT.md` 的术语表——例如 KPI 标签从旧的
"淋浴中"改为"使用中"。术语统一是跨端的硬要求，优先于沿袭旧文案。

### 承载方式：服务端托管在根路径

网页端由 FastAPI 以 `StaticFiles` 挂在 `/`，**注册在所有路由之后**——
Starlette 按注册顺序匹配，`mount("/")` 是兜底，否则 `/api`、`/admin`、`/docs`
都会变成静态文件查找并返回 404。`test_e2e_branches.py` 锁定了这个顺序约束。

nginx 无需改动：它把 `/` 通配代理到应用。

### 接入方式：复用既有契约

旧面板调用的接口，本系统大部分已有，字段名不同：

| 旧 | 本系统 |
|---|---|
| `POST /api/v1/sessions/assign`（`sid`） | 同路径，`cert_no` + 必填 `device_id` |
| `POST /api/v1/sessions/settle` | 同上 |
| `POST /api/v1/photos` | 同路径 |
| WS `{type:'snapshot', doors, devices, time}` | `{type:'door_update', payload:{doors}}` |

**差异要点**：本系统的 WS **只推变化**，不像旧系统连上即推全量，因此进入页面时
先 REST 拉一次兜底。

### 暂未搬入

`/api/v1/tunnel/*`（旧系统的常驻 ADB 隧道）与 `/api/v1/video/*`（视频推流）
本系统没有对应能力；界面节点树也待设备端提供导出接口。这些属于"功能后续加"，
因此 `viewer.html` 里为点击涟漪、长按进度环、准星等交互写的样式**也未搬入**——
提前留着只会成为死代码。

### 正面后果

* 一套样式：视觉调整只改一处，色值分歧消失
* 零构建：改完刷新即可，无需编译步骤或工具链版本管理
* 与 API 同源：无跨域、无额外端口、无独立部署

### 负面后果

* 管理面接口需要 `X-Admin-Token`，界面因此多一个令牌入口
  （旧系统走隧道，不需要）
* 无框架支撑，界面复杂到一定程度后手写 DOM 会吃力——届时再评估
