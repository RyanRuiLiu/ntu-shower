# ADR-0025: hold 改单次布防，恢复等落点

- 状态：Accepted
- 日期：2026-11-21
- 决策者：项目负责人
- 修订：ADR-0024 的第 4 条（「hold 期间 MCU 截止是租约」）被本决策取代，其余条款不变

## 背景

2026-11-21 事故：六台设备点击「今晚延长」后在 00:00–00:02 集体断电。因果链三处叠加，
全部有生产日志与设备日志实证：

1. **预补偿布防的截止少算一个偏移量**。布防写在拨钟之前（此刻墙钟 = 真实轴），拨钟
   把墙钟推前 offset_s；MCU 的钟面检查按拨后钟面走——截止实际在 apply + 租期（00:02）
   到点，而非落点 + 租期（00:20）。
2. **恢复判定等的是被跳过的 close**。close（23:58）一过即清 hold，比落点（00:10）早
   12 分钟——延长的全部意义就是越过 close。
3. **恢复后的按事实重布算出 0 分钟延时**（目标 23:58 对表盘 23:58:19）。

机制层的根：0024 的滚动租约（每 2 分钟重布「表盘此刻 + 租期」）与 MCU 的钟面检查
语义冲突——每次续写的截止可能不晚于已在位的那个，写下去要么被忽略、要么把断电拉前。
MCU 的布防语义见 docs/device-poweroff.md 的实测记录：0xA1 写入的是相对延时，MCU 把它
换算成**布防那刻钟面的一个 HH:MM 截止**，钟面走到即断电（拨过截止立即断电、回拨等量
推迟）。

## 决策

1. **一次布防承担整晚**：施加时一次 0xA1 写入，截止 = 表盘此刻 + 2×偏移 + 余量
   （拨钟把墙钟推前一个偏移，截止必须再让出同样的量），此后不再下发任何布防。
   服务端消失，截止照常到点——到点断电正是期望终态，无需另设失效安全窗口。
2. **恢复等落点**（施加时刻 + 偏移），且零命令：钟面写回由 following_schedule 的
   自动校时承担；其重布按营业时段判定，过 close 不重布——否则延长会被变成 24 小时。
3. **拨钟后作废旧偏差**（device_clock.forget）：旧偏差描述的是旧钟面，写钟后 30 秒内
   的对账动作按旧轴换算会把截止布错轴。
4. **触发窗外的意图 park**；close 已过作废。手动提前点击在对账器里等到窗内施加，
   不再以「下一个 close」为界延长到次日。
5. **布防在位而落点前掉线留痕**：布防可能被 MCU 静默丢弃，漏报会让延长无声失效。
   掉线本身不触发补救——人不在就是断电，方向安全。

## 行业参照

恒温器 Hold Until 的单次覆盖写入（Honeywell：hold 到指定时刻即恢复程序，不再滚动）；
chrony makestep 的「写后重锚」（写钟后旧偏差作废）；DHCP/etcd lease 的失效安全思路
在此被「期望终态即失效安全」取代。

## 后果

- `LEASE_RENEW_INTERVAL_S` / `LEASE_TTL_S` / `_last_arm_at` 删除；`lease_deadline` 列
  语义改为「布防截止到点（真实轴）」，列名沿用不改。
- resume 端点不再要求设备在线（409 移除）；恢复只清状态。
- 落点前的手动 resume 是尽力取消：重布一个更早的截止，MCU 接受更早截止时生效，
  否则被忽略——断电仍落在落点 + 余量。
- 事故时间线以用例钉死（`tests/test_power.py::test_incident_timeline_replay`）。
- MCU 的重布替换规则与 0 分钟延时语义仍未定论，受控实验定论后记入
  docs/device-poweroff.md；单次布防的设计对所有候选结论鲁棒。
