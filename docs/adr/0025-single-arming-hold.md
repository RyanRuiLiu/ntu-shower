# ADR-0025: hold 单次布防——整夜覆盖，恢复写准

- 状态：Accepted
- 日期：2026-11-21（2026-11-22 修订：布防目标改为整夜覆盖、恢复补写准一步，依据当晚业主对语义的裁定；旧称「落点」的概念一律表述为「恢复时刻」）
- 决策者：项目负责人
- 修订：ADR-0024 的第 4 条（「hold 期间 MCU 截止是租约」）被本决策取代，其余条款不变

## 背景

2026-11-21 事故：六台设备点击「今晚延长」后在 00:00–00:02 集体断电。因果链三处叠加，
全部有生产日志与设备日志实证：

1. **预补偿布防的截止少算一个偏移量**。布防写在拨钟之前（此刻墙钟 = 真实轴），拨钟
   把墙钟推前 offset_s；MCU 的钟面检查按拨后钟面走——截止实际在 apply + 租期（00:02）
   到点，而非恢复时刻 + 租期（00:20）。
2. **恢复判定等的是被跳过的 close**。close（23:58）一过即清 hold，比恢复时刻（00:10）早
   12 分钟——延长的全部意义就是越过 close。
3. **恢复后的按事实重布算出 0 分钟延时**（目标 23:58 对表盘 23:58:19）。

机制层的根：0024 的滚动租约（每 2 分钟重布「表盘此刻 + 租期」）与 MCU 的钟面检查
语义冲突——每次续写的截止可能不晚于已在位的那个，写下去要么被忽略、要么把断电拉前。
MCU 的布防语义见 docs/device-poweroff.md 的实测记录：0xA1 写入的是相对延时，MCU 把它
换算成**布防那刻钟面的一个 HH:MM 截止**，钟面走到即断电（拨过截止立即断电、回拨等量
推迟）。

当晚修复版仍把「今晚延长」实现为短延长（截止 = 恢复时刻 + 余量，00:20 断电）。业主指出
语义错配：「今晚延长」的意图是**整夜不关机**——设备带着偏置运行到清晨，次日 auto_open_time
照常上电，而不是午夜后二十分钟就断电。短延长方案还衍生出第二处实证缺陷：偏置存续期
内校正被回退偏置触发，真实断电时刻从布防目标漂移（00:20 → 00:42），运维看到的截止
与实际断电对不上。

## 决策

1. **一次布防承担整夜**：施加时一次 0xA1 写入，断电目标 = **次日 auto_close_time**
   （`off_day_offset=1` 顺延一天），此后不再下发任何布防。拨钟与恢复时刻的写回都
   无法越过这个截止，不存在预补偿算术——偏置存续期内布防截止恒在钟面之外，2026-11-20
   事故的整条因果链不复存在。服务端消失，截止照常到点——到点断电正是期望终态，
   无需另设失效安全窗口。
2. **恢复等恢复时刻**（午夜后 `RESUME_AFTER_MIDNIGHT_MIN` 分钟；偏移量按施加时刻的
   表盘现算。close 在凌晨的晚关门——close 早于上报的 open 且已越过午夜+10——恢复
   时刻改为 close + 该余量：恢复时刻必须落在被跳过的 close 之后），且**墙钟写准是
   恢复自己的第二步**：无条件执行，不依赖 time_sync 开关
   ——偏置不写回，表盘永远快一个偏移量，下一晚施加的恢复时刻算术即被破坏。写准
   失败（离线、上报事实缺失）hold 保持，下一轮重试。
3. **拨钟后作废旧偏差**（device_clock.forget）：旧偏差描述的是旧钟面，写钟后的对账
   动作按旧轴换算会把目标算错轴。
4. **触发窗外的意图 pending**；close 已过作废。手动提前点击在对账器里等到窗内施加；
   午夜后才建立的意图以建立时刻之后第一次到来的 close 为界（今晚的 close），跨日
   存活到触发窗。
5. **布防在位而截止前掉线留痕**：布防可能被 MCU 静默丢弃，漏报会让延长无声失效。
   掉线本身不触发补救——人不在就是断电，方向安全。
6. **恢复时刻前的手动恢复是尽力取消**：先写准，再重布「真实此刻 + 1.5 分钟」的更早
   截止（MCU 接受更早截止时生效，否则被忽略——断电仍由整夜布防的截止承担）；恢复
   时刻后的恢复不取消，设备运行到次日自然关闭。

## 行业参照

恒温器 Hold Until 的单次覆盖写入（Honeywell：hold 到指定时刻即恢复程序，不再滚动）；
chrony makestep 的「写后重锚」（写钟后旧偏差作废，写准本身就是恢复动作）；DHCP/etcd
lease 的失效安全思路在此被「期望终态即失效安全」取代。

## 后果

- `LEASE_RENEW_INTERVAL_S` / `LEASE_TTL_S` / `_last_arm_at` 删除；`lease_deadline` 列
  更名 `arming_deadline`（迁移 c7e2a1d94b50，纯更名），语义 = 整夜覆盖布防的截止
  （次日 auto_close_time，真实轴）。
- resume 不再是零命令：写准是恢复本体；恢复后偏差纪元作废，设备下一帧重新收敛，
  恢复之后不再有任何命令。偏置期间的校正回退漂移随「截止恒在钟面之外」一并消失。
- 事故时间线以用例钉死（`tests/test_power.py::test_incident_timeline_replay`）；午夜后
  请求、重复请求幂等与离线保持均有边界用例。
- MCU 的重布替换规则、0 分钟延时语义与 enable 位行为已由受控实验定论
  （2026-11-21，见 docs/device-poweroff.md §12）：最后写入唯一生效、0 延时无立即
  语义、enable=0 使挂起布防失效。单次布防的设计对所有候选结论鲁棒。
