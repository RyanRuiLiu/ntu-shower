# ADR-0021: 网关凭据校验在 accept 之后，以 RFC 6455 1008 关闭

- 状态：Accepted
- 日期：2026-11-09
- 决策者：项目负责人

- 决策者：项目负责人
- 依据：RFC 6455 §7.4.1、ASGI WebSocket 规范

## 背景

原实现在 `ws.accept()` 之前校验设备凭据，失败时 `close(1008)`。实测（真实 uvicorn + websockets 客户端）：accept 之前的关闭在 ASGI 下只能回 **HTTP 403**，客户端收到的是 `onFailure`，拿不到 WebSocket 关闭码，无法把「凭据被拒」与普通断连区分开。设备端的 1008→自注册分支因此不可达；同时 0.6.7 改「先试后注册」时漏接了 `enroll()` 调用，形成「无凭据→1008→清凭据→重连→仍无凭据」的环，新装 APK 的设备永远注册不上。

## 决策

1. 服务端先 `accept()`，校验失败再以 **1008（Policy Violation）** 关闭——这是 RFC 6455 给策略拒绝定的关闭码，关闭帧能送达客户端的 `onClosed(1008)`。
2. 设备端 `onClosed(1008)` 触发 claim 自注册（判断收敛在纯逻辑 `Enrollment.shouldReEnroll`，JVM 单测覆盖），成功后回调重连；普通关闭码一律只重连。
3. 「先试后注册」保留：本地无凭据也照常发起连接，注册只由 1008 触发，不设按服务端形态分流的兼容分支。

## 备选方案

- 握手前拒绝后靠超时/计数器猜测是否该注册：未选——把凭据策略编码进时序猜测，客户端拿不到确定的关闭码，不可测、易误判。
- 自定义关闭码或自定义注册触发消息：未选——1008 已是标准码，自造协议只会增加两端分叉。

## 后果

- 服务端与设备端共用一套标准语义；端到端链路（accept → 1008 → 自注册 → 带凭据重连）由服务端契约测试与 JVM 单测分别钉住。
- `test_version_consistency.py` 与 `publish_apk.ps1` 从 `build.gradle.kts` 读版本号，三处一致由测试强制。
