# ADR-0011: 楼层状态行的控制边界

- 状态：Accepted
- 日期：2026-10-30（整理入档；原始决策日期见 Git 历史）
- 决策者：项目负责人
- 取代：无

## 背景

本条目汇总该领域的有效决策；原始讨论、实测与取舍见相关代码注释与 Git 历史。

## 决策

- **汇总在服务端，显示在设备端**：设备只读本机 `t_doorlist`，看不到别的楼层；服务端把
  每台设备的空闲喷头数汇总成一份现态，经 `status_line.update` 推给设备。设备不查别的
  设备、不缓存规则、只负责按配置把这一行画出来。
- **条件与屏幕提示共用一套判定，值独立**：状态行有自己的时间窗、星期与占用区间
  （`status_line_condition`），但判定逻辑与屏幕提示同属 `ConditionRule`；服务端不判定
  时间、占用与显隐，只推现态。这样两个窗口可以各自常显或各自只在夜间显示，而不会
  出现两套时间/占用语义。接收方是**所有已信任在线设备**，与 `config.update` /
  `device.update` 同一条口径；刚上线、还没上报喷头的设备也收帧，自己的楼层在首次
  采集前显示「无数据」，其余楼层立刻可见。
- **只报空闲数，不报分母，不写「满」**：「3/7」会被读成「7 台里还有 3 台可用」，而 7
  是喷头总数；只留空闲数就没有这个歧义。0 照写 0，不写一句评价。
- **配色可调，默认取浴室 App 源码里的颜色**：空闲楼层默认 `#6bc600`（`colors.xml`
  的 `title_color`），0/离线/无数据默认 `#999999`（`zitihui`），背景默认 `#0066cc`
  加八成不透明度（`background_blue`），文字默认白色。几个颜色都是配置键，换成
  `bk_hint_ok` #75fc32 或 `booking_code` #02f9f4 不需要发版；默认不选黄色——
  浴室 App 里黄色是预约/使用提示，拿它表示空闲会与现场语义冲突。
- **可用 = 已信任且有活动连接，`free` 只数 `DoorState.FREE`**：已选中不算可用（下一个人
  得先消掉选择），维修中与已禁用更不算。在线但还没上报过喷头的设备 `free = null`，显示
  「无数据」；离线显示「离线」——两者与「0 个空闲」是不同的事实。
- **与屏幕提示是两个独立窗口**：各自一个系统级浮层，各自显隐、位置、字号、配色与背景；
  可以单独出现，也可以同时出现。不合并成同一行、不强制两行、不按优先级互相顶替；
  只有操作遮罩显示时两者一起让位。默认位置（状态行居中 y=8dp、提示左对齐 y=40dp）
  在 13sp 下互不重叠，之后再各自调。
- **提示始终压在状态行上方**：提示用 `TYPE_SYSTEM_ALERT`（KitKat 第 9 层），状态行用
  `TYPE_PHONE`（第 3 层）。两者都是标准应用浮层，都在系统栏（第 16 层）之下；z 序由
  窗口类型决定，不依赖“同类型窗口后加的在上”这种顺序——状态行晚一秒显示也不会翻到
  提示前面。系统栏出现时会盖住两者，这是不越级的直接代价。
- **推送是现态，不是事件**：服务端每秒汇总一次，内容变了就推，没变则 30 秒保活；设备
  90 秒收不到新状态就隐藏，链路断开时立即隐藏。不排队、不回执、不补发——重连后的下一轮
  推送自然恢复，旧状态不会停在屏幕上变成一句假话。
