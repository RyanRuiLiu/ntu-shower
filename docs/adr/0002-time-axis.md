- 决策者：项目负责人
- 取代：无

## 背景

本条目汇总该领域的有效决策；原始讨论、实测与取舍见相关代码注释、`docs/evidence/` 与 Git 历史。

## 决策
>
> 两条轴的定义、三条换算规则、哪个字段属于哪条轴，都在 `docs/ARCHITECTURE.md`「时间轴与口径」
> ——那里是它们的**唯一规范**。这里只记"为什么这么定"与踩过的坑，不复述定义。

- **两条轴的解析函数不可混用**：混了不报错，只是数字归零或偏一整个量。这个错误在本项目里
  犯过两次（一次在推导里，一次在"从设备痕迹推回开阀时刻"里），两次都是静默的——
  `tests/test_derivation_edges.py` 里那几条边界用例就是为它们留的。设备钟的**绝对值**不可信
  （自然漂移 8.5 秒/天，100 天里 16.6% 的锚点落在被改过的时段），而它的**差值**可信：两个
  读数出自同一口钟，差值与被拨动多少无关。
- **对外字段一律在服务端轴上**，设备报的原话只留在原始帧。同一个字段名在两处放两条轴的值，
  读的人分不出来，而"形状相同、含义差一个偏差"比"没有值"危险得多：`door_live` 的三个时间
  字段曾按设备轴存，网页于是把分配时刻渲染成 `00:55`、还把 `|时刻 − 本地时间|` 当已洗时长在计。
