# ADR-0001: 总体取向

- 状态：Accepted
- 日期：2026-10-30（整理入档；原始决策日期见 Git 历史）
- 决策者：项目负责人
- 取代：无

## 背景

本条目汇总该领域的有效决策；原始讨论、实测与取舍见相关代码注释与 Git 历史。

## 决策

- **措辞禁令来自当时那套已删除的自创术语门禁**：被禁的那几个词描述的不是文风，而是一种设计——假定主方案不完整，
  再补一条次等的。本项目取向相反：每条通路各自完整、按场景选。
- **不写兼容代码与数据迁移**：开发阶段允许重建本地库，生产实例的数据不删；schema 只有最初版本。
  结构变更必须同步改调用方；收益是仓库里不存在只在旧数据上成立的暗角。
  唯一的一次性重建是语音固定素材库上线：旧音效导入新表后立即删除旧规则/投递/合成缓存表，
  旧音效源文件保留；它不是随版本保留的双写层，第二次启动不会再执行。
- **不留无用物**，但"当前无人读取"不等于无用：`usage_session`、`door_state_event`、
  `command_audit` 是统计口径的原始数据，删了不可复得，必须先攒。

> 后记 2026-11-14：文中单数表名在 v2 数据层重写中改为复数（`command_audits` 等），以 `server/app/models/` 为准。

- **一改一验**：改完立刻跑门禁，不攒一批再验。命令超过 10 秒说明有问题——测试有 5 秒单例超时，
  超了就是它在等一个永不到来的事件。
- **能简则简**：一个域名、一个端口、一张证书、一个服务进程。少一个组件就少一处会坏的地方。
- **换服务器 = 只改 DNS 记录，零现场**。这条是上一条的推论：没有要改的配置项，就没有上门的理由。
