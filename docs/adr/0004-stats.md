## 决策

- **按指标选数据集，不是一刀切排除异常**。一次会话的真实时长不超过设备的强制释放阈值
  （`service.SESSION_MAX_S`，它的来源是浴室 App 的 `maxbatchtime`——那个值不在本仓库），
  由此分出四个可用集，**判据都能从列上算出来、不落列**：
  - **全量**：出水类。`flow_s` 只累加有观测证据的段，从不高估；
  - **结束时刻可信**：`ended_at − last_seen_at` 不超过那个阈值。占用 / 等待 / 利用率 / 时段类；
  - **盲区**：上式取反。单列成表：采集断线率、可疑占用；
  - **超长占用**：`ended_at − assigned_at` 超过那个阈值。单列成表：门被占着却一直不出水。
- **后两个不是一回事**。实测盲区那组只有个位数，而超长占用有一批——它们的 `last_seen_at`
  紧贴 `ended_at`（盲区甚至为 0），也就是每一帧都被看见了，只是**门被占着却没有出水**。
  会话的结束只依赖"状态变成非占用"，没有任何时长上限；设备那条 20 分钟强制释放管的是出水，
  管不了"分配不开阀"。做占用类指标时这一组会把均值拉偏。
- **利用率的分母不选定一个，全部并列输出**：同一件事有几种算法就出几个名字——出水、占用、
  等待、占着没出水各成一列，比率的分母写在页面上。不替使用者决定他看到的是什么。
- **查询层面不建汇总表**，直接查明细：明细按年计也就十万行量级，而汇总必然与明细漂移。
- **调试账号（后台登记的一个学号，标识不入文档）不排除**：它的频次与零出水率都远高于常人，但**数据
  一致对待**——它在报表上的影响看得见即可，不做特殊剔除。
- **零出水会话全部保留**：那是真实的"刷了卡没洗"，是有意义的行为数据。
- **明细必须从第一天就在**：原始帧全量落库、派生结果单独立表，口径变化后仍可重算。
  这是先落原始层的全部意义。
